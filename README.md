# JFT-Basic Mock Test 01 — Phase 1

## PCでテストする

現在起動中の場合は、ブラウザで http://localhost:8080 を開くと使えます。

起動し直す場合：

1. エクスプローラーを開き、このREADMEが入っている `jft-basic` フォルダーを開く。
2. `Start-Test.cmd` をダブルクリックする。表示されたウィンドウは開いたままにする。
3. ChromeまたはEdgeを開く。
4. アドレス欄に `http://localhost:8080` を入力し、Enterを押す。
5. Name・Class / Sectionを入力する。
6. `Start Test` をクリックする。ここから60分の計測が始まる。
7. 選択肢をクリックして回答し、`Next`で進む。
8. Sectionの最後で`Continue to Next Section`を押し、確認画面の`Continue`を押す。
9. Section 4の最後で`Submit Test`を押し、確認画面でも`Submit Test`を押す。
10. 結果画面の`Download Result`をクリック → 保存先を選ぶ → PDFを保存する。プレビューが開いた場合は共有／ダウンロードを選ぶ。自動保存されない場合は画面の`Save PDF`を押す。結果を確認する。新たに受験する場合は`Start a New Attempt`を押して確認する。この操作で前回の保存データは削除される。

終了する場合は、起動用ウィンドウをクリック → Ctrlキーを押しながらCキー → 必要ならYを入力してEnter。

`index.html`のダブルクリックではJSONを読み込めないため、上記URLから開いてください。アプリの依存パッケージをインストールする作業はありません。このPCのNode.jsを起動用ファイルが利用します。

## スマートフォンでテストする

1. PCで上記の起動用ウィンドウを開いたままにする。
2. スマートフォンの設定 → Wi-Fi → PCと同じネットワークに接続する。
3. スマートフォンのSafariまたはChromeを開く。
4. アドレス欄に `http://11.0.11.191:8080` を入力して開く（作成時のPCのアドレス）。
5. PCと同様に受験情報を入力し、`Start Test`を押す。

PCのアドレスが変わった場合：PCのスタートメニュー →「コマンド プロンプト」と入力 → 開く → `ipconfig`と入力してEnter → Wi-Fi欄の「IPv4 アドレス」を確認 → スマートフォンに `http://そのアドレス:8080` を入力。

接続できない場合は同じWi-Fiか確認してください。WindowsのファイアウォールにNode.jsの通信許可画面が出た場合、信頼できる自宅・学校ネットワークでプライベートネットワークの通信を許可してください。ネットワーク側の端末間通信制限がある場合、スマートフォンからアクセスできません。実機のネットワーク接続は未検証です。

## 実装した機能

- 必須の受験情報入力、50問、60分、4セクション。
- テスト開始時に問題ごとの選択肢順をシャッフルし、表示順にA～Dを付与。
- 採点は固定のchoice.idとcorrectChoiceIdで比較。
- Section 1・2・4は同じSection内のPrevious / Nextと回答保持。
- 次のSectionに進む前に確認し、前Sectionへの移動を禁止。
- Listeningは回答後にのみ前進でき、Previousなし。
- audioScript・正解・解説・source・difficultyは受験画面に表示しない。
- Q26～Q38の13問にMP3音声を収録。Play Audioで各問題最大2回再生できる。回答選択時にも音声は継続する。
- 開始時刻・回答・ランダム順・現在位置・再生回数・提出状態をlocalStorageに保存。
- 残り5分の強調表示、0秒で自動提出。確認画面表示中でも時間切れを提出。
- 250点換算、各Sectionの正答率（整数%に四捨五入）、所要時間、受験情報を表示。
- 白を基調としたPC・スマートフォン対応、キーボード操作、資料の改行保持、表枠内横スクロール。
- 複数タブの同時操作を検出し、継続するタブを1つに制限。

保存先はその端末・ブラウザです。PCからスマートフォンに回答は引き継がれません。ブラウザの保存データを消すと進捗も消えます。端末の時計を操作したり保存データを書き換えたりする不正への完全な対策はPhase 1の対象外です。

## 未実装の機能・拡張位置

Google Sheets送信、Teacher Review / dashboard、School / Class Code、複数学校、複数Mock Testの選択、サーバー側採点、GitHub Pagesなどへの公開は未実装です。MP3音声は全13問組み込み済みです。

`core.js`のTESTにテストID・制限時間・データURLをまとめています。別テスト追加時は別JSON・別IDを用意し、保存キーもテストごとに分離できます。採点は独立したgrade関数なので、将来サーバーへ移す場所が明確です。Teacher Reviewでは確定JSONの正解・解説を使えますが、現在は一覧表示する画面やアクセス制御を作っていません。

Phase 1はブラウザ内で採点するため、開発者向けの操作でJSONの正解・audioScript等は閲覧できます。将来、正解データを秘匿する場合はサーバー側採点と受験用データの分離が必要です。

Reading資料の表示はscript.jsのrenderMaterialにまとめています。Q45～Q50の文字罫線表はpresentation.jsで解析し、HTMLテーブルとして表示します。セルの文字内容・見出し・資料の注記は保持し、配置用の罫線文字とセル前後の余白だけを表示から除きます。表が画面幅に収まらない場合は表の枠内だけ横スクロールできます。JSONは変更していません。

Q07「受付」・Q08「改札」・Q09「道具」には表示時に下線を付け、「Choose the correct reading of the underlined word.」を表示します。問題本文自体は保持しています。

Listeningで回答を選択しても再生中の音声は継続します。問題移動・提出時は停止します。再生中の再度の再生は無効で、最大2回の上限と保存を維持します。

## 音声設定・後からMP3を差し替える（今は操作不要）

音読さんBetaで高品質・速度0.9・ピッチ0・「忠実に読み上げる」を使用しました。女性はEmma、男性はAsh。役名のみの会話は客・患者・利用者にAsh、店員・受付・職員・駅員にEmmaを割り当てました。班長・管理者はAsh、アナウンス・車内アナウンスはEmmaです。同じ人物の声は統一しています。話者ラベルは生成原稿から除き、確定JSONは変更していません。

1. `data`フォルダー内に`audio`フォルダーを作る。
2. `Q26.mp3`などの音声をそこへ置く。
3. `data/audio.json`を次の形式にする：

```json
{
  "Q26": "data/audio/Q26.mp3",
  "Q27": "data/audio/Q27.mp3"
}
```

4. 新しい受験を開始する。各問題のaudioFileにパスが入り、成功した再生ごとにplayCountが増え、maxPlays=2で再生が制限される。

保存済みの受験を開き直すと最新の音声対応表を読み込み、回答・開始時刻・再生回数を保持したまま音声パスを反映します。再生をやり直すために回数はリセットされません。

## 今回の改善

本文・選択肢・資料・表は初期設定LargeでPC28px、スマホ24px、行間1.6です。StandardはPC22px／スマホ20px、Extra largeはPC34px／スマホ30px。Text sizeから切り替え、設定は次回も維持します。長い内容はスクロールで表示します。PCの全4パート進捗は220pxの左サイドバー、スマホはPartsボタンで開閉します。現在のパート名・パート内番号・全体番号・Time Leftのコンパクトな情報行だけをスクロール中も常時表示します。タイトル・文字サイズ設定・パート一覧は固定しません。Student IDは入力・結果・PDFから削除しました。旧保存データも読み込めます。入力項目はconfig.jsのSTUDENT_FIELDSで管理します。

音声はMP3全体の取得とデコードを完了し、約1秒待ってから先頭から再生します。Preparing audio…の間と再生中は連打できません。実際に再生を開始した場合だけ1回加算します。読み込み失敗は加算せず、再試行できます。問題移動・提出は待機予約も取り消します。回答選択は再生を止めません。

結果PDFには日本語氏名、クラス、受験開始日時（Asia/Taipei、UTC+08:00）、得点、各パート正答率、所要時間と非公式スコアの注記を収録します。正解・解説・台本は含めません。日本語は端末の文字描画で画像としてPDFへ格納するため、文字化けしにくい形式ですが文字選択はできません。日時の地域はconfig.jsで変更できます。

実機固有の初回再生症状、iPhone/Androidでの音声出力とPDF保存操作は未確認です。PCブラウザと幅390pxでの検証結果はVALIDATION.mdを参照してください。
